Active selection cannot silently prefer a unique or newer child. resolve_codex_rollout still collects session_meta.id matches. If state_5.sqlite is absent, one match resolves and two or more stay Duplicate. If the file exists, active_index::lookup must return one path; a missing row, a second row, a non-text path, a corrupt file, or a path that is not one of those matches fails the resolve. The SQL is the fixed statement SELECT rollout_path FROM threads WHERE id = ?1, bound with the session argument. active_index_selects_exact_branch_not_a_unique_or_newest_child points the index at one of two retained children and asserts the other child's text is absent, then points it at the root and gets a one-part chain. missing_index_never_guesses_a_paginated_tip expects Duplicate. That is the right revision of unique-tip inference.

The Windows SQLite use is read-only and bounded. LoadLibraryExW loads winsqlite3.dll with flag 0x800, system32 only. sqlite3_open_v2 is called with flag 1, SQLITE_OPEN_READONLY. The busy timeout is 1000 ms. Nonzero SQLite codes fail closed. The column pointer is copied into an owned path before the second step, and the bound CString outlives both steps. Statement finalize and connection close run before FreeLibrary. The test opener uses flag 6 and is not the production path. A readonly WAL connection can still create a sibling shm file; that does not update threads and cannot choose a branch. There is no new crate, process, or network call.

Root identity and virtual offsets match the coframe. lineage::resolve walks history_base from the selected file, caps the chain at 8, and rejects a repeated volume and file index. The returned path and top-level file identity are the oldest ancestor. Child session_meta is validated, then omitted by setting that part's physical_start to the header end. The root part starts at physical 0, so an old cursor remains a logical cursor. Prefix bytes stop at end_byte_offset. The tip appends after that cut. Boundary validation reads at most the 8 MiB record limit, requires a trailing newline, and requires the last record ordinal plus one to equal end_ordinal_exclusive. It does not recount the 3 GB file. Nested parts concatenate in logical order. prefix_only_fingerprint_is_unchanged_and_cut_reads_first_child_payload shows the prefix hash is unchanged and the first child payload starts at the cut. old_cursor_keeps_unread_prefix_then_child_and_excludes_abandoned_tail resumes a prefix-only cursor through the unread gap and the child, excludes the abandoned tail past the cut, leaves the old journal bytes in place, and appends schema 2.

Schema 2 does not rewrite schema 1. A new append uses schema 2 only when source identity history is non-empty. Parser accepts only schemas 1 and 2, and schema 2 must carry two to eight extents whose geometry agrees. SourceIdentity::retains maps an empty stored history onto the live root when the root still starts at logical 0 and physical 0 and the committed end is within the root cut. Once the committed end passes a later segment's logical start, that segment's volume, file index, physical start, and header fingerprint must still match. Replacement, truncation, header mutation, and root reversion therefore fail closed after the cursor has entered that segment. history_identity_pins_shared_child_and_rejects_switch_to_longer_origin locks the boundary: a changed tip still retains at exactly the cut and fails at cut plus one.
