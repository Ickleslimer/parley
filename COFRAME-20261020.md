Private staging versus idempotency. The durable record stores the content hash, an opaque staging name, and the consumption state. It does not store pixels, the client filename, or a client path. Staging lives only in the job directory Rust creates. The cloud copy of the job carries the hash and the job id. A worker that does not have that local directory fails closed. Do not upload the bytes so a remote worker can see them.

Same idempotency key plus the same hash returns the stored outcome and does not restage, re-prompt, or call the broker again. Same key plus a different hash rejects. A replay is not a second chance to start.

Enqueue versus provider-started. Validate shape, count, size, type, session id, and canonical cwd before any pixel file is kept and before ACP initialize. A mismatch cleans nothing because nothing was kept, and it does not move the shared context cursor. Store the rejection under the key so a replay returns that rejection. Once ACP, the broker, or a model token has started, the job is provider-started. Crash, cancel, or restart then cleans staging and records a terminal failure or cancel. It does not re-deliver the image. Resumption that reuses a provider token without a second delivery is a later slice, and only after the trace shows that token exists.
