# Async image implementation boundary

Chosen: real review-only, acknowledgement-required Grok image jobs. Typed ordered
path/SHA-256 descriptors; existing session/original cwd; cached duplicates before
file access; immutable inspected snapshots; job-owned private staging; no automatic
provider replay; original cancellation and strict Stop/receipt checks. Existing
text fingerprints remain byte-identical. Image requests use SHA-256 fingerprints.

Managed image ACP receives only its genuine job binding as a child environment
overlay after inherited binding removal. Native reply fragments feed the existing
durable report parser directly, never fabricated streaming-json. One private,
zero-argument receipt-wait operation wraps the existing verified helper for that
job only. It is absent from synchronous image turns. No shell/file permission,
peek/alert tool, broader native tool allowlist, hook change or new lane grant.

Rejected: sync calls masquerading as jobs, handoff-none, fake ids, Stop retries,
overloaded health tool, provider replay, raw image paths/bytes in durable job
journals or review packets, and mass-swapping older sibling binaries.

Evidence: actual source trace in transport-coframe.request.txt, Grok reports
958f86d1 and43c2d53f (saved and receipted), active14b54 rollback candidate. Baseline
in this detached worktree passes461 unit/4ignored and9CLI tests. Permission and
visible-request source checkpoints314b119/6697466 are ancestors of runtimefa2363;
this is preparation, not sibling-profile promotion acceptance.

Unknowns/gates: native ACP must deliver report fragments early enough for the
private wait; the real canary must publish, wait while unacknowledged, accept exact
receipt and terminate successfully. Cancellation/recovery cleanup and same-hash
idempotency need tests. No live activation until those gates and actual diff review
pass. Sibling compatibility/rollout remains a separate bounded objective after
this feature, without any root or policy expansion. No commits/push/main changes.
